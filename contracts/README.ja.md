# `contracts/`

totsuka が**管理していない**コードとの、機械可読な合意を置く。サブディレクトリ
1 つが契約 1 本で、どれも「型を共有できない独立した実装 2 つ以上」から読まれる。

| 契約 | 読む側 |
|---|---|
| [`slack-event-gateway/`](slack-event-gateway/README.ja.md) | `plugins/task-source-slack` と `services/slack-event-gateway` —— Cargo workspace が別々で、しかもゲートウェイはフォークされうる（[ADR-0072](../ai-docs/decisions/adr-0072-slack-event-gateway.md) 決定 9） |

## 何がここに入り、何が入らないか

このリポジトリのフィクスチャの大半はこの意味での契約では**ない**。既定は
「所有者と同じ場所に置く」である:

- `plugins/agent-ide-herdr/schemas/` —— このプラグインが依存している herdr の
  Socket API の一部。正は herdr 側にあり、プラグインが追従する。
  `scripts/herdr-schema-check.sh` がこのパスから読む。
- `crates/plugin-protocol/tests/fixtures/` —— プラグインプロトコルのワイヤ形式の
  見本。正は `plugin-protocol` にあり、各プラグインはファイルではなく依存として
  受け取る。

ここに置いてよいのは、次の**両方**が成り立つときだけ:

1. **読み手の少なくとも 1 つがこのリポジトリのビルドの外にある。** workspace の
   別メンバーでも依存クレートでもなく、別にビルドされるもの —— 場合によっては
   別の人の手で。
2. **正を持つ側が、その正を依存として渡せない。** ここに正が**無い**わけではない
   —— 決定 7 は totsuka の `project()` を参照射影と定め、`gateway_contract.rs`
   もそう書いている。だがゲートウェイは別の workspace でビルドされ、フォーク
   されうるので、その関数を `use` することが永久にできない。**その読み手にとって
   正が取りうる唯一の形がフィクスチャ**であり、外の誰かに宛てて書かれたものを、
   その人が中を見られない側に置くことはできない。

1 だけが成り立つなら所有者の側に置いて、そこを指せばよい。外の読み手が正を持つ
クレートにそのまま依存できるなら、写しは要らない。どちらも成り立たないなら、
それはただのテストデータである。

## ここに足すときの決まり

- **言語に依存しない形式にする。** JSON であって、Rust のモジュールでも生成された
  バインディングでもない。別言語での再実装がそのまま読めること。
- **単体で閉じる。** リポジトリの外の読み手が解決できない参照を書かない ——
  クレートパス、`#[test]` の名前、内部の識別子は入れない。
- **上へ辿って見つける。** `../` の段数を数えない。ハードコードしたパスは
  ディレクトリが動いたとき失敗するのではなく**何も見つけず、ケース 0 件の
  スイートは緑になる**。`slack-event-gateway/` の読み手は 2 つとも
  `CARGO_MANIFEST_DIR` から上へ辿り、見つからなければ panic する。
- **契約ごとに `README.md` / `README.ja.md` を 1 組置く。** 何を固定するのかと、
  なぜ見本ではなく契約なのかを書く。
