* **Update**: 推奨サイドバースニペットを実機で使って壊れた 3 点を直した（#417）。**いずれも [ADR-0039](/decisions/adr-0039-herdr-sidebar-identity.md) D6 の制約として書き足した**。(1) **報告されたトークンだけで組むと、手で起動した agent とオペレータ自身の space で entry が `state_icon` だけになる** — `rows` はグローバルなので、entry のどこかに常に非空のトークンが要る。(2) **agents 行の主語に `workspace` を使わない** — 1 つの space に別リポジトリの tab を足せるので、totsuka の space で Infra.mac を触っている agent が「totsuka」と名乗る。(3) **長さに上限のないトークンは行の最後**（幅が足りないと後続が押し出される） [サイドバー設定手順](/operations/herdr-sidebar-setup.md)
* **Update**: **agents と spaces のトークン語彙は包含関係ではなかった。** 「agents = spaces ＋ tab/pane/agent/…」と書いていたのは誤りで、**agents に `branch` / `git_status` は無く、spaces に `tab` / `pane` / `agent` / `terminal_title*` は無い**（herdr 同梱の設定テンプレートで確認）。あわせて `branch` は space 単位のトークンなので、1 space が複数リポジトリの tab を持つと意味を成さない点も明記した [herdr サイドバー設定](/references/herdr-sidebar-config.md)
* **Update**: **`source` はトークン名の名前空間ではない**（実機）。source A が入れた `repo` を source B が上書きでき、B の `--clear-token` は A の値ごと消す。`source` を定数にした理由（32 スロット制限）は変わらないが、**同じ pane に 2 つの書き手が居てはいけない**という帰結が別につく — 手で起動した agent に repo を出すシェルフックは、`TOTSUKA_JOB_ID` を見て totsuka の pane では走らないようにする必要がある。`agent.start` を挟んでもトークンが保たれることも確認した（D1 の「報告してから起動する」順序が依存している点） [herdr Socket API](/references/herdr-socket-api.md)
* **Update**: スニペット自身と、それが依拠する記述の残りをレビューで詰めた。**推奨スニペットが `[ui]` テーブルを重複させており、既存 config に貼ると TOML の重複テーブルで設定ファイルごと読めなくなる**（未知キーのように無視されない）状態だった。`[ui.sidebar.agents].rows` のフォールバックも 3 制約を満たしておらず、claude 以外の agent で同じ症状が出る。制約 1 は行単位ではなく **entry 単位**で、常に非空と言えるのは spaces の `workspace` と agents の `workspace` / `agent` だけ（`terminal_title_stripped` は OSC タイトルが出るまで空）と直した。制約 3 も「可変長」ではなく「**長さに上限のない**」トークンが対象で、`$repo` / `$mode` は先でよい
* **Update**: トークン語彙の出典が **herdr 同梱の設定テンプレート（宣言）であって挙動の実測ではない**ことを明記した。「列挙に無い＝描画されない」は herdr を信じた推論である。あわせて `[ui].sidebar_width` について「実行中セッションに効く」とは書かないことにした — `session.json` にも同名の値が永続化されており、`reload-config` 後もそちらは変わらなかったが、**優先関係は測っていない**
