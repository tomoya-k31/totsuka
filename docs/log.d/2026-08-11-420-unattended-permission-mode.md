* **Creation**: [ADR-0041](/decisions/adr-0041-unattended-permission-mode.md) — 無人 pane が承認プロンプトで止まる問題（#420）に対し、**3 ツールとも「人間に確認を求めない」設定で起動する**決定。claude は `permissions.defaultMode = "auto"`、codex は `--ask-for-approval never`、opencode は `--auto`。[ADR-0036](/decisions/adr-0036-read-only-violation-fails-the-task.md) が plan ゲートを外して消したはずの停止は、**消えたのではなく `ExitPlanMode` から `Bash` へ移っていた**（実測: 個人設定を外した claude は `manual` で起動し、allowlist 外の Bash で `Do you want to proceed?` のまま止まる）。開発機で再現しなかったのは、そのマシンの `allow` と `defaultMode = "auto"` が効いていたため
* **Update**: `[tools]` の kind 別既定 argv が変わった（#420）。codex implement は `--ask-for-approval on-request` → **`never`**、codex plan は `--sandbox read-only` に **`--ask-for-approval never` を追加**、opencode は plan / implement とも **`--auto` を追加**。**エージェントにできることは広げていない** — claude の `deny` は全 permission mode で適用され、codex の `--sandbox` は承認ポリシーとは別フラグ、opencode の `--auto` は CLI 自身が「explicitly denied を除いて自動承認」と説明しており `totsuka-plan` の deny マップは残る。`mode_args` / `plan_args` を明示すると既定を丸ごと置き換えるのでこれらのフラグも消える点は変わらない [設定リファレンス](/development/config-reference.md) / [orchestrator-core クレート](/components/orchestrator-core.md)
