* **Update**: reqwest を 0.12 から 0.13 へ上げた（Renovate #882）。0.13 で TLS の feature の意味が変わったので、どちらの使い手も挙動が変わらないように選び直した。**ワークスペース**は、0.13 の `default-tls` が rustls を指すようになったので `native-tls` を明示した。Socket Mode の WebSocket（tokio-tungstenite の `native-tls`）と同じプラットフォームの TLS スタックを使い続けるためである。あわせて、0.13 で既定から外れた `form` を足した（Slack の transport がフォームを送る）。**Event Gateway** は `rustls-tls-webpki-roots` が無くなった。0.13 の `rustls` はプラットフォームの検証器、つまりファイルシステムのルート証明書を読むので、そのままでは「ルートはバイナリに焼き込み、ベースイメージの `ca-certificates` に依存しない」という設計が崩れる。そこで `webpki-root-certs` の Mozilla バンドルを `tls_certs_only` に渡し、そのルートだけで検証するようにした。焼き込んだルートで googleapis と slack.com に TLS 接続でき、ルートを空にすると検証で失敗すること（＝プラットフォームのルートを使っていないこと）を確かめた。aws-lc-rs になったゲートウェイのイメージも、Alpine/musl のビルダーでそのままビルドできる。[task-source-slack](/components/task-source-slack.md) の TLS の記述も直した。
