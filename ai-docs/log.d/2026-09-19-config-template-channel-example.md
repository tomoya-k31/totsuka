* **Fix**: [orchestrator-cli](/components/orchestrator-cli.md)。`totsuka setup` が書き出す `config.toml` 雛形の**チャンネル監視の例が起動しない**のを直した。`trigger = { channel = true, … }` になっていたが `channel` はチャンネル ID の**文字列**でなければならず、`plugin_sdk::watch` が「which is not a channel id → write the platform's channel id as a string」で `initialize` を落とす。**雛形はそのままコメントを外して使うためのもの**なので、この 1 行をコピーした人は totsuka を起動できない。`git log -S` で追うと雛形を作った #707 から一貫して誤っており、以来そのままだった。**なぜ検査をすり抜けたか**が本質で、`scripts/config-template-lint.sh` はコードの config struct と雛形を双方向に突き合わせるがキー**名**しか見ない —— `channel` というキー自体は正しいので通る。値の型・必須の組み合わせ・そもそも起動するかは管轄外だった。加えてこの行だけ説明コメントが無く（他は全部 `# slack: …` が付く）、目視でも浮いて見えなかった。回帰テストを task-source-slack 側に置いた: 雛形から `# trigger = { … }` の例を全部抜き、**キーが全て `TRIGGER_KEYS` に収まるもの**（= この source が受け取りうるもの）を実際の `workflow_reactions` / `resolve_watch_triggers` に通す。フィルタを「slack: と書いてある行」ではなくキー集合にしてあるので、github の `status` や notion の `filter`、`assignee` は自分から外れる（コメント文言に結合しない）。orchestrator-cli 側ではなくプラグイン側に置いたのは検証関数がモジュール私有だからで、雛形はパスで読むだけ、crate 依存は足していない。改竄して落ちることを確認済み（元のエラー文まで再現する）。
