* **Update**: [ADR-0061](/decisions/adr-0061-workflow-handoff.md)（#568）。read-only profile へ引き渡すとき worktree を detach するようにした。引き渡しは worktree を持ち越すため、implement 段がブランチに載せた worktree を design 段が引き継ぐと read-only 検査（[ADR-0045](/decisions/adr-0045-read-only-is-not-guaranteed.md)）が違反と判定し、**質問待ちのエージェントの pane を閉じていた**（実機で観測: 質問提示から 3 秒、`pane released` が `session_end` より先）。検査に引き渡しを教えるのではなく、検査が拠り所にしている不変条件（worktree は detached で渡る）を回復させる形で直した: detach に加えて `tasks.branch` も消す（worktree が掃除で消えていると `acquire_worktree` がこの列から再作成してブランチに載せ直すため、detach だけでは同じ失敗に戻る）。あわせて掃除の data-loss ガード `is_detached_with_commits` に `--not --branches --remotes` を足した — 「どの ref からも到達できない commit」を守るはずが `base..HEAD` を数えるだけで、ブランチ先頭で detached な worktree を毎回 `Dirty` と判定し、worktree と pane を永久に残していた。ブランチ ref は残るので前段の作業は失われず、read-only 段が自分でブランチを作った場合は従来どおり止まる。診断文の「it was handed over detached, so the agent ran git」という断定も、detach に失敗しうる以上は実態に合わせて弱めた（`plan_mode_side_effect` 側も同様）。
