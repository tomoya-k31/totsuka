* **Creation**: [ADR-0010 worktree 掃除の3段化（判定→pane→worktree）と session/release の追加](/decisions/adr-0010-worktree-cleanup-pane-release.md) — protocol 0.2.0 の Slack 実機検証で発覚した「正常完了時に herdr pane を閉じる経路が無く pane が単調増加する」問題（[#210](https://github.com/tomoya-k31/totsuka/issues/210)）への対応方針を記録。(1) `cleanup()` を `decide_cleanup`（判定）と `remove`（実行、dirty 再チェック = TOCTOU 対策。データ損失 > pane 喪失）に分割し、`Remove` 判定のときだけ pane を閉じる3段化（`DirtySkipped`/`Retained` の pane = 人間の導線は保持）、(2) protocol **0.2.1** で `session/release` RPC を追加（capability は `pane_control` 相乗り・新設せず）、(3) 同一性検証は `expect_cwd`（= worktree パス、DB 正本・一意）を主キーに「比較可能なペアが1つでも不一致 → 拒否、全ペア比較不能 → degrade-open で閉じる」（`expect_label` は層違反を避け未送出の拡張点）、(4) 保持プリセット `keep_7d`/`keep_28d`（config 層の糖衣、既定値 manual/immediate は不変）、(5) worktree sweep 間隔を `SETTLE_TICK`（200ms）から分離（60s・config 非露出。done 直後の pane close は即時のまま）。孤児 pane の検出は #211（doctor）に分離。
