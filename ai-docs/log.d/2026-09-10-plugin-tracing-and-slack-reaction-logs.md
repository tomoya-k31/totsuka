* **Update**: [plugin-sdk](/components/plugin-sdk.md) に `runtime::init_tracing()` を足し、プラグイン 7 本すべてをそこへ寄せた（#640）。各 `main.rs` が手書きしていた `tracing_subscriber::fmt().with_writer(stderr).init()` は**2 点とも黙って壊れていた**: `RUST_LOG` を読むのは*自由関数*の `fmt::init()` だけで、**ビルダーの `.init()` はレベルを INFO に固定する** —— つまり `RUST_LOG=<plugin>=debug` はエラーも警告も出さずに無視され、**全プラグインの `debug!` が到達不能**だった。加えて ANSI が常時 on で、ホストが stderr をパイプで拾って JSON ログへ再出力するため、**エスケープ列（`\u001b[2m` 等）がログファイルに残り**、まさにログを読んで調べている最中に読めなくなっていた。付随して 7 本の `tracing-subscriber` 直接依存は不要になったので外し、SDK を使っていなかった `agent-ide-herdr` / `agent-ide-orca` / `notifier-macos` に `plugin-sdk` 依存を足した（`arch-lint` の plugins → protocol/sdk 境界の内側）。
* **Update**: [task-source-slack](/components/task-source-slack.md) のリアクション経路に診断ログを入れた（#640）。エンベロープ受信（`socket_mode`）・リアクション到着・**判定 5 経路それぞれの drop 理由**（操作者でない / トリガー絵文字でない / self-DM / dedup 済み / bot 投稿・subtype / 別経路が確保済み）を `debug!` で出す。これまで全経路が無言の `continue` だったため、**「Slack がイベントを送っていない」と「届いたがフィルタで落ちた」が外から区別できなかった**。実際に「リアクションを付けてもタスクが立たない」を追ったとき、この 1 行が無いために数時間かかっている（原因は Slack アプリ側の Enable Events が Off で、`hello` 以外のエンベロープが 1 つも届いていなかった）。あわせて `check_scopes` が `x-oauth-scopes` を読めないときに**無言で検査ごとスキップ**していたのを `warn!` にした —— 警告ゼロの起動が「検証済み」に見えてしまい、`reactions:read` の有無を確定させるのに余計な往復が要った。
