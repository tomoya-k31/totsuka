* **Update**: [click-to-focus セットアップ](/operations/click-to-focus-setup.md) を `docs/` の**生成元に昇格**させ、`docs/click-to-focus-setup.md` / `.ja.md` を作った。これまで手順は OKF バンドル側にしか無く、**`docs/` にあるのは `setup-playbook` の 1 行だけ**（「`terminal-notifier` の導入と bundle id の設定」）で、そこから読者が知りようのないものが 4 つあった —— `brew install terminal-notifier`・bundle id の調べ方・**どのファイルに書くか（`plugins/macos.toml`）**・**何のキーに書くか（`backend` / `activate_bundle_id`）**。後ろの 2 つは推測不可能で、しかも `backend` を切り替えないと `activate_bundle_id` だけ書いても効かない。実際に手順を組み立てるのに `ai-docs/` を読む必要があった。click-to-focus は開発者向けの内部事情ではなく**利用者が自分の環境でやる設定**なので、slack-quickstart と同じ性質のものとして扱う（[ADR-0047](/decisions/adr-0047-ai-docs-human-docs-split.md)）。生成物には「ファイル名を間違えても黙って効かない」ことと、**それを検出する方法**（出鱈目なキーを 1 行足して `config validate` が弾くか見る）を残した。`setup-playbook` の生成物側からは新ページへリンクし、`docs/index.{md,ja.md}` にも行を足した。`human-docs` スキルは表・本文の件数・**`description`（＝トリガー条件）**の 3 箇所を更新した —— description を直さないと、次に誰かがこのソースを編集してもスキルが発火しない。
