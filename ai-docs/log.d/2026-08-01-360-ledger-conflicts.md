* **Creation**: [ADR-0031 docs の元帳（log.md / index.md）は生成物にして並行 PR の衝突源を構造的に消す](/decisions/adr-0031-docs-ledger-conflicts.md) / **Update**: [CLAUDE.md](/CLAUDE.md) — `ai-docs/log.md` を `ai-docs/log.d/` の断片から生成する形に変えた（[#360](https://github.com/tomoya-k31/totsuka/issues/360)）。**衝突は運ではなく構造の帰結だった**: log.md は直近 60 commit のうち 55 件が変更し、そのうちログを触った直近 40 commit は **40 件すべてがファイル先頭への挿入**で、これは「新しい日付が上」＋「同日はエントリを追記」という規約の直接の帰結である。コンフリクト中の PR は `refs/pull/N/merge` を作れず **CI が一切走らない**ため、代償は「解決 → 再検査 → force-push → CI 全周回」1 式（PR #288 は開いている間に 3 回払った）。各 PR が**新規ファイル**を 1 枚置く形にすればその衝突源が消える。あわせて `index.md` の concept 一覧を `scripts/okf-index-build.sh` の管轄にし、`.gitattributes` で `merge=union` を宣言した。

  **`index.md` は「生成」ではなく「正規化」**にした点が設計の要である。並び順と表示タイトルは index.md 自身が持つデータで、スクリプトはそれを保存する — 並びは curate されていて**ファイル名順ではない**（`components/` はレイヤ順、`glossary/` は概念の導入順、`product/` は英語 canonical が先で、ファイル名昇順にすると `.ja.md` が先に来てしまう）。タイトルも frontmatter と意図的に違うものが 10 件ある（`orchestrator-core` ⇄ `orchestrator-core クレート`）。機械が持つのは description の転記し直し・未掲載の追記・消えた行の削除・重複の畳み込みの 4 つだけ。

  **issue が本命として挙げた log.md 用の merge ドライバは、実装して測ったうえで不採用にした。** ドライバは `ai-docs/log.d/` を読んで再生成するが、git はマージ中に**全パスの内容マージを終えてから** worktree と index を更新するため、走る時点で相手側の断片は**どちらにも存在しない**（実測: worktree にも `git ls-files` にも自分側の断片しか無い）。結果として相手のエントリが丸ごと欠けた log.md を、コンフリクトを出さずに生成してしまう。包含チェックのガードを足すと破損は防げるが必ずその分岐に落ちるので衝突は 1 件も減らず、`clone` ごとの `git config` という手間と「0 件になる」という守れない約束だけが残る。受け入れ条件は「コンフリクトしない**または**コマンド 1 手で決定的に解決する」なので、後者（`bash scripts/okf-log-build.sh && git add ai-docs/log.md`）で満たす。

  **元帳がはじめて機械検査の対象になった。** 従来 log.md に対する検査は日付見出しの形式（`log-format`）だけで、順序も重複も内容も見ていなかった。その帰結として、**PR #310（OKF v0.2 移行）の `rumdl --fix` が落とした `# Log` という迷子の H1 が、ファイル末尾に 3 週間気づかれずに残っていた**（`.rumdl.toml` は MD025 を意図的に無効化しているので rumdl も拾わない）。移行で除去し、以後は `log-sync` が即座に落とす。`log-sync` / `index-sync` の判定は lint 側に書き写さず**ビルダーへ委譲**した — 同じ規約を 2 箇所で実装すると「lint は通るのに生成すると差分が出る」が必ずいつか生まれるため。

  移行は 1 日 1 断片（21 個）で、**生成結果は移行前とバイト一致する**（差分は上記 `# Log` の除去のみ）。1 エントリ 1 断片（226 個）にしなかったのは、過去の日付には新エントリが来ないので粒度を上げる利得がゼロで、しかも生成時に空行の入り方が変わって全 345 行が差分になりレビュー不能になるから。同日内の並びは断片ファイル名（= slug）の昇順で、**時刻順ではない** — slug は任意の語なので、後から足したエントリが先のものより上に出ることがある。**同日内の並びに意味は持たせない**（この PR の出力自体がそうなっている: `2026-08-01-360-…` が `2026-08-01-archive` より上に出る）。
