* **Update**: [config.toml 雛形](/development/config-template.md)を**全設定パターン網羅**に書き直した（#705）。約 70 行 / 33 キーから 472 行 / 162 キーになり、core の全キーに加えて 7 プラグイン（github / notion / slack / discord / herdr / orca / macos）の設定テーブルが 1 キー 1 行の要約付きで載る。末尾に**レシピ集**を置き、対話ウィザードの 4 レシピが符号化していた「動くワークフローの組み合わせ」（`trigger` → `profile` → `agent` → `on_success` の対、`implement` に `output` を書かないこと）を、コメントを外せばそのまま動く形で移した。`scripts/config-template-lint.sh` を CI（`clippy / rustfmt` ジョブ）に組み込み、以降キーを増やして雛形を直し忘れると PR が落ちる
* **Update**: 網羅性検査に 2 つの逃げ道を足した。`OPAQUE_ALLOWED` は「雛形に書くがどの struct にも現れないキー」の宣言で、`[[workflows]].trigger` と workflow の追加プロパティ（`reaction` / `channel` / `publish` 等）が該当する —— core が `toml::Table` のまま保持して渡すので（#554）、解釈するコードはあってもフィールドが無い。行内マーカー `lint:raw` はその行を丸ごと読まない指定で、`trigger.filter` に書く Notion のフィルタのように**第三者の DSL をそのまま渡す**値のためにある。どちらも理由付き 1 行を要求する
* **Update**: 雛形が **1 行も有効行を持たない**ことを `the_skeleton_activates_nothing` が検査するようにした。生成しただけでは何も設定されないのがこのファイルの契約だが、400 行のコメント例を編集していると有効行は容易に紛れ込み、それはそのリリース以降 `init` を走らせた全員に効く。網羅性検査はファイルをテキストとして読むのでコメント行と有効行を区別できず、両方あって初めて「全部載っていて、何も効いていない」が言える
