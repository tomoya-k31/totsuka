* **New**: [herdr の暗黙契約（schema に載らない依存）](/references/herdr-implicit-contracts.md)。totsuka が herdr の **schema に一度も現れない振る舞い**へ依存している 5 箇所（C-1 metadata token 値の 80 文字上限／C-2 pane id の `w1:p1` 形式／C-3 herdr 内部の 5 秒下限／C-4 `workspace.create` の env が root pane に適用されること／C-5 `pane.split` の shell pane が env を継承しないこと）を一覧にし、**それぞれの確かめ方**を付けた（#521）。[ADR-0055](/decisions/adr-0055-herdr-schema-typed-wire.md) の型化も CI の schema 差分も**この層を 1 つもカバーしない** — schema に無いもの・schema にあっても意味が現れないもの（pane id は単なる `string`）・黙って切り詰める挙動は、いずれも差分に出ないからである。C-1 / C-2 は実機 herdr 0.7.5 でコマンドごと実測して確認した（`80 chars / 240 bytes`、`pane_id` の接頭辞と `workspace_id` の一致）。
* **Update**: **C-5 だけ性質が違うことを明記した。** 他の 4 つは「壊れたら動かなくなる」ので遅かれ早かれ気づくが、C-5 は壊れても**何も起きない** — `TOTSUKA_HOOK_TOKEN` を持ったシェルが人間の隣に常駐するだけで、タスクは今までどおり完了する。したがって実機検証の**必須項目**とし、`.claude/skills/live-e2e/` に S0（herdr の版を上げたら最初に回すシナリオ）を新設した。**確認コマンドは値を絶対に画面へ出さない形にする**: `printenv TOTSUKA_HOOK_TOKEN >/dev/null 2>&1 && echo TOKEN=set || echo TOKEN=unset` — 出力を捨てて終了コードだけを見る。**`echo "${TOTSUKA_HOOK_TOKEN:+set}${TOTSUKA_HOOK_TOKEN:-unset}"` は危険で、`:-` は変数が設定されているとき値そのものへ展開する**（`setSECRET…` と出る）。レビューで指摘されるまでこちらを書いており、しかも同じ段落で「値は出さない」と書いていた — **安全だと書いた式そのものが漏らしていた**。一度出すと pane 履歴・`pane.read`・シナリオを回したエージェントの transcript に残る。
* **Update**: **C-1 について「totsuka はこの上限に依存していない」ことを明記した。** 識別に使う `totsuka_task` は上限を超えるなら切らずに**省く**（切れた機械識別子は無い識別子より悪く、ラベル経路が正しいフォールバックになる）ので、上限が変わっても壊れない。測るのは、上限が「**拒否**」に変わっていないかを見るためである — 拒否に変われば `report_metadata` がエラーを返し、identity 報告が丸ごと落ちる。**「依存しているから測る」と「変化が別の壊れ方を生むから測る」は違う**ので、確かめる理由まで書いた。
* **Update**: **C-4 に独立した確認手順は無い**ことを明記した。root pane で動いているのは Claude Code の TUI でシェルではないので、`herdr pane run` を打ってもコマンド文字列がプロンプトとしてエージェントに渡るだけである。観測点は**完了検知そのもの** — env が root pane に届かなければ Stop フックが Orchestrator を叩けず、タスクは完了報告を出さない。**S1 がフック完了で通れば C-4 は成立している**ので、専用の手順を足すのは重複であり、しかも動かない手順を足すことになる。あわせて C-6（`agent.start` の `name` は `[a-z][a-z0-9_-]{0,31}`。schema 上は素の `string`）を一覧へ追加した — これは**破れたら大声で壊れる**（`invalid_agent_name` で dispatch が落ちる）ので確かめ方は要らず、`agent_name` の生成規則を触るときに「なぜ `t-` を前置しているのか」を辿れるようにするために載せてある。
