* **Refactor**: `Engine.released_panes` のキーを task id から **セッション行 id**（`sessions.id`）へ変え、release の一回性を `ReleaseMode` で呼び出し側が選ぶ形にした（[#486](https://github.com/tomoya-k31/totsuka/issues/486)、[orchestrator-core](/components/orchestrator-core.md)、[ADR-0010](/decisions/adr-0010-worktree-cleanup-pane-release.md)）。**振る舞いは不変**（テスト 1,206 件が一致）。task 単位のメモは「新しい pane ができたら手で無効化する」規約を要求し、その**違反が無言**だった — 書き忘れると新しい pane が二度と解放されず、症状は「pane が 1 枚ずつ増える」だけで、これは #210 が起票された症状そのものである。dispatch のたびに新しいセッション行ができるので、行 id をキーにすればメモは自動的に無効化され、[#481](https://github.com/tomoya-k31/totsuka/issues/481) で `dispatch.rs` に足した 2 つの手動リセットは消えた。`released_panes` への参照は `finalize.rs` の中だけに閉じ、他モジュールからは触れない。**リファクタの過程で、2 つの呼び出し側の要求が逆であることが判明した**: 掃除は「削除が失敗し続けても再送しない」（一回性が要る）、再 dispatch は「これから新しい pane を開くので古いのが消えていることが前提」（一回性があってはいけない — メモに記録された `released: false` は「既に消えていた」と「同一性拒否で閉じなかった」の両方を意味し、後者では pane が生きている）。当初は一回性を `release_pane` の内側に閉じ込めたが、#481 の回帰テストが**再 dispatch 側の release が抑止されること**を検出したので、`ReleaseMode::{Once, Always}` で呼び出し側が選ぶ形にした。**この区別はテストより先に型が守る**: `Always` の呼び出しを 1 つでも `Once` に変えると、ワークスペースの `warnings = "deny"` の下で `dead_code`（variant `Always` is never constructed）としてビルドが落ちる。メモの刈り取り（bounding）は `forget_release_memos` が `list_sessions` で当該タスクの全行を落とす — リトライしたタスクは複数行を持つので、最新行だけ落とすと古い行がプロセスの寿命ぶん残る。
