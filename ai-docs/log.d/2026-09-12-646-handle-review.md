* **Update**: `Task.handle` のレビュー指摘（#646）を反映した。**`{handle}` プレースホルダはパス安全化してから埋める** — プラグインが書く文字列なので、`../outside` を返すソースがあると `/state/{handle}/…` のようなテンプレートで worktree のルートを脱出できた。`{task_id}` / `{source}` を生のままにしているのは「既存の運用者テンプレートの出力を変えない」ためで、**新設のプレースホルダにはその制約が無い**のでここだけ扱いが違う。あわせて **Slack は `conversations.info` が失敗したときに handle を付けない**ようにした（`NameCache::channel` は生のチャンネル id へフォールバックするので、そのまま渡すと「読めない id を避ける」という handle の目的が一時障害で裏返る）。[config-reference](/development/config-reference.md) の `{worktree_name}` の説明も handle 込みに直し、`docs/` を再生成した。
