* **Update**: [agent-ide-herdr](/components/agent-ide-herdr.md) の herdr レスポンス読み取りを `serde_json::Value` の手掘りから**生成型**へ移した（#519、[ADR-0055](/decisions/adr-0055-herdr-schema-typed-wire.md)）。`transport::call_typed` / `to_params` を足し、`pane.get` / `pane.list` / `workspace.list` / `workspace.create` / `pane.read` / `agent.start` の応答と、22 メソッドすべての params が生成型を通る。型化が変えるのは基本的に「どこで気づくか」だけで、「気づいた後どうするか」は呼び出しごとに既に設計されている（`pane.split` の失敗は warn のみ、`workspace.create` の失敗はタスク失敗、`pane.read` の失敗は診断テキストが空になるだけ）。**ただし「振る舞いは一切変えていない」と書くのは強すぎる**: `session/attach` は `agent_status` 欠落時に `unknown` へ落として前値維持していたが、それは 5 版すべてで `required` なフィールドに対する防御であり、実際に発火するのは herdr が本当に消したとき ＝ 知りたい瞬間なので、**意図的にエラーへ変えた**。逆に `session/list` は #416 が意図して入れた degrade（読めない応答は「何も所有していない」）を**型化で失いかけたので明示的に復活させた** — `doctor` の孤児 pane 検出が乗っている best-effort な診断面で、herdr が変な答えを返しても失うのは診断であってコマンドではない。`state.rs` の `agent_status` 写像も生成 enum ベースになり、**「知らない状態は前値維持」が `_` の腕ではなく `AgentStatus::Unrecognized` という名前**になった。
* **Update**: 型化で **`FakeHerdr` が実 herdr と乖離していた**ことが判明し、6 箇所直した（`workspace.create` の `root_pane` に `agent_status` / `focused` / `revision` / `terminal_id` が無い、`WorkspaceInfo` の 8 必須フィールドのうち 6 つが無い、`AgentSessionInfo` の 4 必須フィールドのうち 3 つが無い、など）。**手書きのテストダブルは、schema と突き合わせる仕組みが無いと必ずずれる** — 実 herdr が送れない形の応答が、それまで全テストを緑で通していた。再発防止に、fixture ビルダが生成型でデシリアライズできることを検査するテストを足した。
* **Update**: 型化で **2 つの誤解**も判明した。①**`workspace.create` だけは生成型で読んではいけない。** 生成型どおりに読むと、`root_pane` が欠けている・壊れているときに `NewWorkspace` が出来る**前に**落ち、後始末に要る id を誰も持たないまま **作った workspace を live な pane ごと漏らす**（後始末の**順序**の問題であって形の問題ではない）。**緩め方を 2 回間違えた**: `Option<PaneInfo>` はキー欠落しか吸収せず、`Option<{pane_id: String}>` へ狭めても `{"pane_id": 1}` で落ちる — **serde は `Option` の内側のエラーを伝播する（飲み込まない）**。落ちない形は「serde にエラーで答えられる問いを投げない形」＝生の `Value` から 2 つの id を拾うことだけだった。生成型（`WorkspaceCreatedEnvelope`）は「herdr が約束しているもの」の記録として残し、その変化を報せるのは CI の schema 差分（マージ前）が担う。②`events.subscribe` の `pane.exited` は schema 上**ユニットバリアントで `pane_id` を取らない** — 購読はグローバルで、totsuka が送っている `pane_id` は herdr が無視するキーである。それでも送り続けるのは `transport::subscribed_panes` が**totsuka 自身のため**にそれを読み返しているからで、pane ごとの絞り込みは `classify_exit` が自前でやっている。
* **Update**: あわせて `config/validate` が `ping` に加えて `workspace.list` を 1 回**生成型でパース**するようにした。`ping` の答えはスカラ 3 つで、ADR-0055 の前提どおりバージョン番号は応答の形を追跡していない。これで「この herdr の応答をこのビルドは読めない」を、**タスクを取り込んで worktree を切る前**に `totsuka doctor` が名指しできる。
