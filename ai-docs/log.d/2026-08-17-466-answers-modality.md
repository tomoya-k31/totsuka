* **Update**: `totsuka setup --answers` を隠しフラグから文書化されたモダリティへ昇格させた（[#466](https://github.com/tomoya-k31/totsuka/issues/466)、[orchestrator-cli](/components/orchestrator-cli.md)、[setup Playbook](/operations/setup-playbook.md)）。**リポジトリが自分と矛盾していた**のが発端で、Playbook は dotfiles に置く新マシン手順として推奨しながら「hidden フラグなので `--help` に出ない」と釈明まで書き、コード側のコメントは「not a product feature」と宣言していた — 釈明が要る時点で隠す判断のほうが誤りだった。Gancarz の原則⑧（captive user interface を避ける）の主張は「対話 UI が悪い」ではなく「他のモダリティを塞ぐな」であり、totsuka は非対話経路を**持っているのに見えない**状態だった。あわせて端末なしのエラー文が `--answers` を案内せず `init` の手編集へ誘導していたのを直した（`init` は全行コメントの雛形しか書かないので、端末なしで動く config が欲しい呼び出し側には答えでない）。`--bundled-dir` は本物のテスト用仕掛けなので hidden のまま。
* **Update**: 回答ファイルの `recipe` をメニュー位置から**安定キー**へ変更し、`ANSWERS_VERSION` を 2 へ上げた（[#466](https://github.com/tomoya-k31/totsuka/issues/466)）。公開契約にする以上、位置インデックスは成立しない — レシピを 1 つ挿入・並べ替えするだけで既存ファイルが黙って隣のレシピを選び、**範囲チェックは通り `version` も動かないので誰も気づけない**。既存ファイルは世界にゼロ（dotfiles・`~/.config/totsuka`・リポジトリ内 fixture すべて）だったので、互換シムを置かず v1 は拒否した — シムを置けば取り除こうとしている位置インデックスの意味論を永久に運ぶことになる。**版はファイルの他の部分より先に読む**: 全体をデシリアライズしてからでは、v1 の `recipe = 0` が `invalid type: integer` として出て利用者に対処のしようがなく、version フィールドが仕事をしない。`RECIPES` の探索は `recipes::by_key` 1 箇所に集約した（対話経路のメニュー選択だけは、その場で返った位置なので添字のままでよい）。
