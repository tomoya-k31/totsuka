* **Feature**: [ADR-0063](/decisions/adr-0063-trigger-assignee.md)（#572）。取り込みの assignee ゲートを `[[workflows]].trigger.assignee` へ移した。従来はプラグイン全体で「未アサイン **または** 自分」がハードコードされており、**未アサインが常に取り込まれる**ので「通常は人間がタスクを取り、AI に渡したいものだけアサインする」という制御が書けなかった。語彙は `@me` / `@none` / `@any` / login / 配列（OR）で、**省略時の既定 `["@me", "@none"]` が旧ゲートと同一**である。旧ゲート（`assignable_to_me`）は github / notion 両方から**削除**した —— 前に残して「書かれていたらバイパス」にすると、`assignee = "teammate"` のような**書けるのに効かない設定**が作れてしまうため、経路を 1 本にした。特殊語の `@` は衝突回避で、`me` / `none` / `any` はどれも実在しうるログイン名である（`assignee = "any"` は「`any` というユーザー」を意味する）。語彙と照合は `plugin_sdk::AssigneeFilter` に置き、**共有するのはキー名と値の書き方だけ** —— 何と突き合わせるか（github は Issue 組み込みの assignee と `github_login`、notion は `property_map.assignee` と `notion_user_id`）は各プラグインが持つ。`status` と違い `assignee` は core 予約キーではない（core は読まない）。notion は前提が 2 つとも任意設定で**どちらも欠けると黙って効かなくなる**ため、`assignee` を書いたら `property_map.assignee` 必須・`@me` を含むなら `notion_user_id` も必須として `initialize` で落とす。`status` を伴わない `assignee` 単独トリガーは配送に lane identity が付かず 1 タスク 1 回になるので、起動時に警告を 1 行出す（label 単独トリガーが既にそうなっているのと同じ性質なのでエラーにはしない）。
