* **Update**: [task-source-github](/components/task-source-github.md) / [task-source-notion](/components/task-source-notion.md) から **`result/publish` の実体を削除した**（#398、[ADR-0033](/decisions/adr-0033-workflow-profile.md)）。成果物はエージェントが自分で書く（`gh` / Notion MCP）ので、Orchestrator が書き戻す経路は要らない。manifest と `initialize` の `outputs` 宣言も外したので、`output = "source"` を書いた workflow は `config validate` が弾く（F-83）。両プラグインの `version` を 0.3.0 へ。
* **Update**: 削除は**連鎖した**。github は `client.publish` → `ADD_COMMENT_MUTATION` → `fold_long_content` / `FOLD_THRESHOLD` が丸ごと死に、**GitHub トークンの必要権限が `Issues: Read and write` から `Issues: Read` へ下がった**（GraphQL 操作も 5 → 4）。notion は `client.publish` → `APPEND_BATCH` と、`blocks.rs` の**書き込み方向だけ**（`markdown_to_blocks` / `classify_line` / `text_block` / `chunk_chars` / `MAX_RICH_TEXT_LEN`）。読み取り方向（`blocks_to_markdown` / `rich_text_plain`）はページ本文をタスクに載せる経路が使い続けているので残る —— ADR-0033 の「`blocks.rs` の削除」という書き方は広すぎた。
* **Update**: `setup` のレシピ 3 本から `output = "source"` の上書きを外した（[orchestrator-cli](/components/orchestrator-cli.md)）。**コメントが理由を誤って説明していた** —— 「the card has to be written back for the status transition to mean anything」とあったが、カードを動かすのは `on_success` の `task/update_status` で、`output` とは独立の RPC である。`human-sign-off` は profile を持たないため `output` の明示が必須なので、`none` を書いた。
