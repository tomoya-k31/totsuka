* **Update**: プロトコルの宣言が**実際に読まれていること**を `scripts/arch-lint.sh` で機械検証するようにし、それに引っかかった 5 件を削除した（protocol **0.5.0**、[#496](https://github.com/tomoya-k31/totsuka/issues/496)、[ADR-0052](/decisions/adr-0052-declaration-consumed.md)、[plugin-protocol](/components/plugin-protocol.md)）。**削除は結果であって主眼ではない。** 死んでいたのは `Capabilities::plan_mode`（plan/implement の分岐は `ExecutionMode` と profile が担っていて経路に存在しない）／`Capabilities::task_submit`（0.2.0 で `tasks/fetch` が消えた時点で情報量ゼロ。起動できる task_source は例外なく push 型で `true` 以外を取り得ない）／`Capabilities::resume_session`（dispatch の resume 判定は**プラグインではなくツール側の** `tool_caps.resume` を見る。唯一の役割は `hook_capable()` の OR 項）／`error_code::PROTOCOL_VERSION_MISMATCH`（互換検査は spawn の**前**にホスト側で終わるので、プラグインが返す機会が原理的に無い）／`error_code::CAPABILITY_UNSUPPORTED`（ホストは宣言された capability しか呼ばない）の 5 つで、**いずれも到達不能であって単に未使用なのではない**。**これは再発だった** — `design_preview` がまったく同じ形で 1 世代残り（#356→#411）、0.2.3 で「次の破壊的バンプで削除」と宣言した `TaskDispatchParams.hook` も消えるまで丸 1 世代かかっている。**このリポジトリは「宣言だけの猶予」が守られないことを既に 2 回実証しており、3 回目を人間の注意力で防ぐ計画には根拠がない。** さらに悪いことに `plugin-dev-guide` は `plan_mode` と `task_submit` を意味のある宣言として例示し、`task_submit` は「必須」とまで書いていた — **作者はそれを読んで宣言し、何も起きない**。検査（`declaration-consumed`）の設計で効いているのは**探索範囲を宣言の向きで分けた**点で、`Capabilities` は「プラグインが宣言し Orchestrator が読む」ものなので消費者は core/cli の `src` だけを見る（ここを広げると herdr が `plan_mode: true` と書いているだけで「消費されている」ことになり、検査が自分の目的を打ち消す）。`error_code` は両側が発行・照合するので protocol 自身以外すべてを見る。どちらも `mock_plugin` と `tests/` は数えない（**テストダブルが立てているだけの宣言は、本番では誰も読んでいないのと同じ**）。フィールドは**アクセス**（`.field`）だけを数え初期化（`field: true`）は数えない。コメント行も数えない（「`.plan_mode` を読む」という doc comment があるだけで死んだフィールドが生きて見える）。`DECLARATION_EXEMPT`（`<name>=<理由>`）の存在こそが主眼で、**放置と意図した猶予を区別できるようにする**ためにある。`resume_session` は削除ではなく **`hook_completion` への置換**で、旧設計は `resume_session || diagnostics_snapshot` という **de-facto のシグナル**を使っており、どちらのフラグも「hook」とは言っていないため作者は文書化されていない規約を知らないと opt-in できず、「セッション再開はできるがフックは話さない」プラグインには**それを言う手段が無かった**。**`diagnostics_snapshot` は統合しない** — 実在の RPC をゲートしており、畳むと「フックで完了を報告する agent は必ずスナップショットも返せる」という新しい要求を暗黙に課す。`-32001`/`-32002` は**番号を再利用しない**（外部プラグインが定義を見て分岐している可能性を否定できない）。**ワイヤは壊れない**（`Capabilities` に `deny_unknown_fields` が無く、古い manifest の `plan_mode = true` は読み飛ばされる）が、**フィールドを読むコードは壊れる**ので protocol は 0.5.0 へ上げ、バンドル 6 本の上限を `<0.6` にした。検査は**削除より先に**書き、5 件を正しく検出することを確認してから削除した（監査で grep 特定した集合と完全一致）。さらに**新規に死んだ宣言を足しても捕まる**ことを別途実測している — 5 件を消せることだけ確認して終わると、検査が「今の状態」にしか効かない可能性を残すため。
