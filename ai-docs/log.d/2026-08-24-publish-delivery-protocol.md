* **New**: [ADR-0057 publish の配送方式と worktree 掃除を workflow 単位で上書きできるようにする](/decisions/adr-0057-per-workflow-publish-and-cleanup.md)。Slack の `:books:`（triage）の報告を承認なしでスレッドへ直接投稿し、workflow ごとに worktree/pane の掃除を変えるための設計（#548）。**[ADR-0003](/decisions/adr-0003-slack-reply-assistant.md) の「承認フロー必須」を workflow 単位の opt-out へ条件付きに緩める** — triage の報告は「issue を立てた」という事実の通知で、承認が守りたいもの（本人名義の*発言*を勝手に出さない）が掛かっていない。`answer` 系の既定は据え置き。キー名は `approval` ではなく **`publish = "draft" | "direct"`**（`verification = "human"` と「human が 2 種類」になる衝突を避け、`draft` はプラグインの確立した語彙で現行挙動の名前そのもの）。
* **Update**: [plugin-protocol](/components/plugin-protocol.md) — protocol **0.5.2**: `ResultPublishParams.delivery`（#548）。**Slack プラグインは publish 時に profile を知らない**（params は task_id / content / format、`PendingMention` は座標と送信者だけ）ので、配送方式は core が `[[workflows]].publish` から決めて渡し、プラグインは従う。欠落 = `draft`（0.5.2 より前の Orchestrator はその挙動に対して書かれている）。**未知の値も `draft`**（`PublishDelivery::Unrecognized`、`#[serde(other)]`）— 2 つのモードの差は「人間のゲートを飛ばすか」であり、読めない指示でゲートを飛ばすのは誤る側が逆。読むのは slack だけ（github / notion は #398 以降 publish を受けない）で、それでよい — このフィールドの意義は汎用性ではなく、方針を運用者が書いた core config に置くこと。
