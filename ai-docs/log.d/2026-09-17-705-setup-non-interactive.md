* **Creation**: [ADR-0077 setup は対話をやめ、全設定パターンを書いた config.toml を生成して編集を促す](/decisions/adr-0077-setup-writes-the-whole-surface.md)（#705）。[ADR-0028](/decisions/adr-0028-setup-wizard.md) を**置き換える**ので、あちらを `status: deprecated` にして後継へリンクした（機密の値を扱わないという決定 5 だけは現行でも生きている）。当時なぜ対話を選んだかと、それが到達できなかった範囲の両方が次の設計の材料になるので、ファイルは削除せず残す
* **Update**: `totsuka setup` から対話を廃止した。残る質問は**使うプラグインの複数選択 1 問だけ**（`dialoguer` の `MultiSelect`。ワークスペース初の端末制御依存で、`crossterm` を丸ごと引く `inquire` ではなく `console` 経由の前者を採った）。非対話経路は `--plugins <csv>`（`all` / `none` も受ける）で、TTY が無く未指定なら **exit 2** —— 既定の選択を置くと選んでいないプラグインが入り、空にすると成功した実行と見分けがつかない。綴り間違いも同じ理由で黙って無視せずエラーにする。`--secret-backend`（`op` 既定 / `bw` / `keychain` / `cmd` / `env`）は**選んだ形を config.toml の参照行にも書く** —— 端末の登録コマンドだけ切り替えると `op://` だらけのファイルの上で `security add-generic-password` を案内することになる。`--answers` / `--save-answers` / `--yes` は削除した（運ぶべきものが「回答」から「設定ファイルそのもの」に変わった）[orchestrator-cli](/components/orchestrator-cli.md)
* **Deprecation**: `totsuka init` を廃止し `setup` に統合した。対話を外すと両者は「非対話でディレクトリと config.toml を作る」まで同じになり、コマンドが 2 つ並ぶ理由が無くなる。`config not found` 系のエラーが案内する先も `totsuka setup` に変えた
* **Update**: 生成される config.toml は**有効行が `version = 1` の 1 行だけ**で、残りは全部コメントである。したがって直後に `config validate` が通り、かつ何も動かない。**導入したプラグインを `enabled = true` にしない**のもここに効いていて、`config validate` は enabled なプラグインを実際に起動するので、`[github].token` がコメントのまま有効化すると、セットアップを確認するためのコマンドがそのセットアップ自身で落ちる。既存 config がある場合は**足りない節だけを追記**し、既存の行は 1 バイトも変えない —— これが「1 月に github を選んだ人が 3 月に `[notion]` の雛形を docs 抜きで手に入れる」経路であり、書き換えでなく追記なのは追記先が利用者のシークレット参照を持つファイルだから
