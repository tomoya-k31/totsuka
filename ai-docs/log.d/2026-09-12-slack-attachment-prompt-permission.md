* **Update**: [task-source-slack](/components/task-source-slack.md) の添付セクションが、**エージェント自身の経路を塞がない文面**になった（[設定リファレンス](/development/config-reference.md) の `body_attachment_header`）。実機検証で「エージェントは permalink から file id を切り出して自力で中身を読む」ことが分かった一方、**出荷している既定文はその逆を指示したままだった** —— 「名前・種類・サイズだけが分かっています」と列挙して permalink を数に入れず、「添付を読めていないことを返信に書いてください」と言っていた。唯一動く経路からエージェントを遠ざける文面である。既定文を「the content was not handed over ／ where a line carries a link, fetch the file from it yourself ／ 取れなければ推測せず読めていないと書く」の 3 段に組み直した。**このキーは見出しと括弧内で言語が違う**: 見出し（`## 添付ファイル（{count} 件）`）はペインを見る人間が読むラベルなので利用者の言語、括弧内はエージェントへの指示なので英語である（[ADR-0054](/decisions/adr-0054-prompt-language-policy.md) に Amendment を足した —— 決定 3 はキー名で「`body_*` は日本語」と列挙していたが、**分類の根拠はキー名ではなく「その文が誰に話しかけているか」**であり、1 つのキーが両方を持つ形は想定されていなかった）。**②を条件形にしているのは `permalink` が `Option` だから**で、リンクが載らない添付に無条件の指示を出すと存在しない handle を指すことになる。**文中で指してよいのは、そのプロンプトに実際に書かれているものだけ**という規律も明文化した —— エージェントが読むのは指示文と本文だけで、`totsuka` というシステムも「タスク」という作業単位も、そこからは見えない。この文面は初稿で「totsuka は中身を取得していません」、次案で「このタスクに含まれていません」と、**2 度続けて読み手が識別できないものを主語にした**。残った文面は「渡されていません」と言い切ってから直下の行を指す形で、どちらも立っている場所から見える。他のプロンプト既定値は全てこの規律を守っており（grep で確認）、破っていたのはこのキーだけだったので、再発しないよう `defaults.toml` のコメントに失敗例ごと残した。**ツール名は意図的に出さない** —— 名指しすると、それを持たないエージェントに存在しない道具を探させる。あわせて **スレッド文脈行にも permalink を載せる**ようにした（`（添付: <name> <permalink>）`）: 名前だけの行は file id が取れず、エージェントにとって行き止まりで、起点メッセージの添付だけが読めてスレッド内の添付は読めないという非対称ができていた。コード側の doc コメント 4 箇所（`the content never reaches the agent` / `the agent cannot fetch it` 等）も**実機の事実と正面から食い違っていた**ので直した。デフォルト検査は「中身を取得していません」と「自分で取得できる手段があれば使ってください」の**両方**を pin する —— 片方だけでは、どちらの半分が落ちても検査が通ってしまう。
