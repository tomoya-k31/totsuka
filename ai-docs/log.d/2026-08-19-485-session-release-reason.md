* **Update**: protocol 0.4.2 — `SessionReleaseResult` に **`not_released`**（`gone` / `refused` / catch-all の `unknown`）を足し、`refused` のときだけ dispatch を fail-fast させた（[#485](https://github.com/tomoya-k31/totsuka/issues/485)、[plugin-protocol](/components/plugin-protocol.md)、[orchestrator-core](/components/orchestrator-core.md)、[ADR-0010](/decisions/adr-0010-worktree-cleanup-pane-release.md)）。`released: false` は「pane が既に無い」と「pane が生きている」の**両方**を意味しており、この 2 つは**新しい pane をこれから開く呼び出し側にとっては正反対**である — 後者だけが「次の dispatch は生きた pane と衝突する」を意味する。[#481](https://github.com/tomoya-k31/totsuka/issues/481) はまさにその衝突で、区別できないために dispatch は素通しにするしかなく、エージェントプラグインの `agent_name_taken` という自前の語彙で数秒後に落ちていた。いまは原因を名指しして止まり、次の一手（手で閉じてから retry）まで言う。**patch 昇格**（0.4.1 → 0.4.2）なのは、0.x で minor を上げると `<0.5` で束ねた同梱 manifest を、どのプラグインも読む必要のないフィールドのために全部弾くため。**欠落と `unknown` は 0.4.2 以前の振る舞いへ縮退する** — 2 つの意味が正反対である以上、推測すれば半分は外す。`NotReleased` に `#[serde(other)]` の catch-all を置いたのは、将来増える理由で**レスポンス全体が読めなくなる**のが、助言でしかないフィールドの代償として重すぎるからで、wire fixture でその縮退も固定した。**`/code-review` が設計の前提を突いた**: 当初は「同一性不一致 = `refused`」としていたが、pane id は位置ベースなので不一致は「その id が別の pane を指す」としか言わず、**タスク自身の pane が消えたのか移ったのかを語らない** — 前者なら agent 名は空いていて dispatch は成功したはずで、fail-fast は偽陽性のうえ retry も同じ refusal を引いて自己回復できない。そこでプラグイン側が `expect_cwd`（タスク毎に一意な worktree パス）と `session/list` を突き合わせ、**その worktree に自分の pane が残っているか**を実データで確かめてから答えるようにした（材料が無ければ `gone` へ縮退）。テストは対照で張ってある: `refused` を返すモックでは 2 回目の `task/dispatch` が**一度も出ない**こと、`gone` を返すモックでは従来どおり 2 回とも出ることの両方を見る（修正を無効化すると前者が落ちることを確認済み）。**この issue は「`refused` が実機で観測されてから着手する」と決めて一度見送ったもので、その判断を覆して実装した** — 観測を待つ側の根拠（起きていない問題のためにプロトコルを広げない）は今も有効だが、判断は依頼者のものである。
