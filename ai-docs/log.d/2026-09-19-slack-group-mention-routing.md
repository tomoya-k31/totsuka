* **Feature**: [task-source-slack](/components/task-source-slack.md)（[ADR-0081](/decisions/adr-0081-slack-group-mention-routing.md)）。所属ユーザーグループ宛のメンションを、宛先グループごとに別の workflow へ振り分けられるようにした（`trigger = { mention = true, to_group = ["S0ONCALL"], repo = "web-app" }`）。`profile` / `agent` / `repo` が違う独立した workflow を宛先別に持てる。**既存設定は無変更で動く** —— `to_group` を書かなければ route は catch-all 1 つで [ADR-0080](/decisions/adr-0080-slack-mention-trigger-marker.md) 以前と同じ。**一致の優先は「具体的な方が勝つ・順序非依存」**で、`[[workflows]]` の並びは影響しない: Slack のメンションは片方が必ず catch-all という非対称な構造なので、定義順 first-match（F-81）を採ると「catch-all をうっかり上に書く」が一撃で下の全部を到達不能にする。定義順が効くのは**同率の tie-break だけ**（`@oncall @design` のように別グループを名指した 1 メッセージが 2 route に一致する場合で、これは設定として正しいので起動時には落とせない）。メッセージ内の出現順は採らない —— 挙動が**メッセージを書いた他人のタイプ順**に依存し設定から予測できなくなるため。この 2 つの規則は**ルートの並び順そのもの**として実装してあり、`ReactionTriggers::resolve` が「group route を定義順、catch-all を最後」に組み立てるので前から舐めるだけで両方になる（舐める側は規則を知らない）。`to_group` は**所属グループの部分集合に限る**（ADR-0025 と同質の緩和を避ける）。タスク ID は `{profile_prefix}:{group_id}:{channel}:{ts}` で、**workflow 名ではなくグループ ID を入れた**: 調べたところ現状 workflow のリネームは何も壊さない（`tasks` の識別子は `UNIQUE (source, source_task_id)` で `workflow` は属性、リネーム後も同じ行が見つかり #565 の引き渡しが worktree とセッションを保ったまま移す）ので、workflow 名を ID に刻むと**現状より悪くなる**。どのグループを prefix に使うかは**メッセージではなく route に聞く** —— メッセージ側から採ると catch-all がたまたまグループを含んだスレッドで勝手に分裂する（実装中に踏み、`an_unclaimed_group_still_reaches_the_catch_all` が捕まえた）。`trigger.repo` は `task/lookup` も LLM 分類も飛ばして即 submit し、会話が settle 済みのリポジトリより優先する。**`repo_pin` と「bot 名義で出す」の結合を切った**: `post_as` は `repo_pin.is_some()` から導出されていて、根拠は「`repo_pin` を立てるのは watch だけ」という暗黙の前提だったので、group route が `repo` を持てるようになると**グループ宛メンションへの返信だけが黙って bot 名義に変わる**ところだった（本人名義の代理返信は [ADR-0003](/decisions/adr-0003-slack-reply-assistant.md) の中心的な性質）。**catch-all は「残り全部」**を受け続ける（名指しされていない所属グループ宛も落ちてくる）—— 「個人宛のみ」にするのは挙動変更で、group route を 1 つ足しただけで無関係なグループのメンションが黙って来なくなるため、ノイズ削減は独立した決定として扱う。`to_group` があって `usergroups:read` が無ければ**ハードエラー**（永久に一致しない route を黙って抱えないため）。所属の照合は `usergroups.list` を要するので **`initialize` だけができ、オフラインな `config/validate` には届かない** —— 失効トークンを検出できないのと同じ区分で、形（配列か・`S…` か・空でないか・`mention = true` があるか・同じグループを 2 つの workflow が claim していないか）は両経路で検査する。mention workflow は watch リゾルバに渡さなくなった（SDK は `channel` の無い `repo` を「壊れた watch」として拒否するため）。
