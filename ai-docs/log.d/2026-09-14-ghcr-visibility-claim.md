* **Update**: [リリース Runbook](/operations/release-runbook.md) と [slack-event-gateway](/components/slack-event-gateway.md) の「**ghcr のパッケージは初回公開時に private になり、リポジトリが public でも可視性は継承されない**」という断定を、実測に置き換えた。**初回リリース（v0.7.6）でそうならなかった** —— 可視性ゲートは 1 回目で `package visibility: public` を返して通過し、手作業は発生していない。匿名のトークンで manifest が 200 を返すこと・`linux/amd64` が存在することも別途確認した。手順書が「赤くなるはずです」と言っているのに緑で通ると、読んだ人は**何か間違えたのかと探し始める**ので、断定のほうを直した。**なぜ public で出たのかは調べていない**（利用者名前空間かつ public リポジトリという条件の帰結なのか、GitHub 側の既定が変わったのか）。分かっているのは観測した事実だけなので、そこは推測で埋めず「調べていない」と書いてある —— **1 つの未検証の断定を別の未検証の断定に置き換えるのでは何も直らない**。**ゲート自体は残す。** 条件が違えば private で出うる以上、private のまま出れば「ジョブは緑、デプロイする人だけが落ちる」という最悪の形になり、コストは API 呼び出し 1 回である。`release-please.yml` のコメントも、予測ではなく「検査する理由」を述べる形に書き直した。
