* **Fix**: クラッシュ窓中に queue されたタスクが、**プラグインの復帰を待たずに終端 `Failed` へ落ちる**問題を直した（[#499](https://github.com/tomoya-k31/totsuka/issues/499)、[ADR-0051](/decisions/adr-0051-plugin-supervision.md) に節を追加、[orchestrator-core](/components/orchestrator-core.md)）。クラッシュした `Plugin` は再起動が**成功**するまでエンジンのマップに残るので、`resolve_dispatch_target` が capability しか見ないと**死んだハンドルへ dispatch が解決する**。**2 つの時計が噛み合っていない**: dispatch の自動再試行は `DISPATCH_RETRY_LIMIT` 回 × `SETTLE_TICK` 間隔で 1 秒未満に尽きるのに、最初の再起動バックオフだけで 1 秒ある。**#495 の PR で一度実装して取り下げた** — 素朴に park すると `crash_on_dispatch`（その dispatch 自体がプラグインを殺すケース）でタスクが終端へ行かなくなり、既存テスト 2 本（`e2e_agent_crash_fails_task_and_orchestrator_survives` / `failed_hook_dispatch_rolls_back_reserved_session`）が壊れた。**今回の要点は「エージェントの状態だけでなく、そのタスク自身の再試行回数も見る」こと**である。停止中でも**そのタスクの自動再試行が 0 回なら park**（スロット解放・`Queued` のまま）、**1 回以上なら通常の経路で予算を使い切らせる**。この差が `crash_on_dispatch` を救う — **まだ何も試していないタスクは他人のクラッシュの巻き添えなので待てばよく、自分の dispatch が失敗し続けているタスクは自分が原因かもしれないので予算を使い切るべき**である。加えて**見放し済み**（予算切れ / `restart = false` / spec 未記録）のプラグインは `Failed`（「再起動されない」と名指しする）— これが無いと park が無限になる。`abandoned_plugins` は**`escalate_dead_plugin` の中で立てる**: 呼び出し側 3 箇所に書くと「諦めた」と「dispatch がそれを知っている」がずれる。**liveness の判定は capability ゲートより先**に置く（死んだプロセスの宣言した capability は宣言のままなので、先に見ると間違った問題を、しかも終端の `Failed` として報告する）。`first_backoff` を縮める案は確率を下げるだけで構造ではないので採らない。報告は `blocked_on_agent` でタスクごとに 1 回だけ（先例は `blocked_on_tools`。200ms ごとに同じ警告を出さない）。テストは pure な 4 分岐 2 本 + e2e 1 本で、**e2e はクラッシュ窓を実際に作る** — mock source に `submit_delay_ms` を足し、タスクの到着をエージェントのクラッシュ**より後**に置いた。**最初に書いた e2e は即時 submit で、検知と競合して落ちていた**（失敗理由も `/nonexistent` での git 失敗であってゲートではなく、DB の `events` を読むまで誤診していた）。**タイミングで通ったり落ちたりするテストは、振る舞いを検証していない。** park を無効化すると e2e が `failed: 1` で落ちることを実測済み — これは #499 の症状そのものである。
