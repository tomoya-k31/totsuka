* **Update**: [slack-event-gateway](/components/slack-event-gateway.md) の公式イメージを ghcr.io に出すようにした（#660、[ADR-0072](/decisions/adr-0072-slack-event-gateway.md) 決定 9）。**OpenTofu はソースからビルドできず、イメージの URL を要求する。** 「まず自分でビルドして自社の Artifact Registry に push してください」と言うと、OpenTofu を整備する目的（構築を自動化できること）と正面から衝突するので、リポジトリが公式イメージを出してモジュールの既定値にする。会社での利用では変数 1 つで自社レジストリに差し替えられる。**版付けは totsuka 本体と揃えた** —— 独立させるとイメージとレコードを読むプラグインのあいだに手作業の互換表ができ、誰も参照しない。契約は適合テストスイートとして凍結されている（決定 7）ので、有用な問いは「どの totsuka リリースのものか」であり、タグがそれに直接答える。**`:latest` は出さない** —— OpenTofu 側は正確なバージョンを固定するので、浮動タグがあると `tofu apply` が黙ってデプロイ内容を変えられるようになり、signing secret を持つサービスで「勝手に入れ替わる」性質は持ちたくない。イメージは musl 静的リンク + distroless の `static`（`nonroot`）で、**パッケージマネージャもシェルも libc も入っていない** —— CVE を当てる先が `Cargo.lock` とベースイメージ 2 つしか無い代わりに、**再ビルドしない限り何も直らない**。ベースイメージは**ダイジェストで固定**した（GitHub Actions を SHA で固定するのと同じ理由で、signing secret を持つコンテナの起点をタグに委ねない）。あわせて `reqwest` の TLS ルートを `native-roots` から `webpki-roots` に変えた —— 前者はベースイメージが `ca-certificates` を積んでいることに依存し、`scratch` に差し替えた瞬間に**ビルドではなく実行時の TLS エラー**で全 publish が壊れる。イメージの中身は totsuka が保守する一級の成果物になったので、**ベースイメージの脆弱性監視方針と供給鎖の説明**（誰がビルドし、どう検証できるか。provenance attestation を含む）を [依存関係ハイジーン](/development/dependency-hygiene.md) に追記した。`Dockerfile` は**リリース時にしか使われない**ので、壊れていても気づくのがタグ作成後になる —— `ci.yml` の `gateway` ジョブに「このディレクトリが変わった PR でだけ `docker build` する」ステップを足して、壊れた Dockerfile が赤い PR として出るようにした。
