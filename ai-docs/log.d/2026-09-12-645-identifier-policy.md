* **Creation**: [ADR-0071 タスク識別子の命名](/decisions/adr-0071-task-identifier-naming.md) を追加した（#645）。herdr の agent name・orca の worktree 名・Orchestrator の worktree ディレクトリ名を `<prefix><task 番号><sep><hash8>` の 1 つの規則に揃え、制約の宣言（各ツールの `IdentifierPolicy`）と生成手順（`plugin-protocol` の `identifier`）を分ける。読める半分を source id から**内部 task 番号**へ移したのは、切り詰めた source id が人間にとって何も識別していなかったからで、番号ならログの `task_id=` と `totsuka task retry <n>` に直接つながる。`job_id` を使わないのは `hook_completion` を宣言しない agent（orca）へ永久に届かないためで、protocol 0.7.1 で `TaskDispatchParams.task_number` を足して**毎回**送る。ADR-0032 D-2 はこれに置き換わり、D-3（`agent_name_taken` を孤児の徴候と読む）は前提ごと維持される — 名前に session row を含めない決定はそのための要件である。
* **Update**: [plugin-protocol](/components/plugin-protocol.md) に `identifier` モジュールを追加し、`version` を 0.7.1 に更新した。[agent-ide-herdr](/components/agent-ide-herdr.md) のテスト節を、消えた `agent_name` の性質検査から「宣言する制約が herdr のものであること」の検査へ書き換えた。[herdr の暗黙契約](/references/herdr-implicit-contracts.md) の C-6 は、依存箇所を共有モジュールへ差し替えたうえで「**herdr が検査するから大声で壊れるのであって、こちらが正しいからではない**」ことを #645 の実例（32 文字の予算が 1 文字はみ出す条件を満たした task だけが恒久的に dispatch 不能になった）付きで明記した。
