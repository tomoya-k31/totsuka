* **Update**: macOS の Keychain バックエンドを keyring 3 から keyring 4 の系統へ移した（Renovate #887）。keyring 4 は `keyring-core` とストア別のクレートに分かれ、`apple-native` feature は無くなった。`keyring` の既定 feature（`v1`）でも同じ `Entry` API が使えるが、その場合は Secret Service・Windows などの、どのターゲットでもビルドしないストアの依存まで `Cargo.lock` に載る（+709 行。`cargo audit` / `cargo deny` と Renovate の対象にもなる）。そこで `keyring-core` と `apple-native-keyring-store` に直接依存し、`platform::macos` は `Cred::build(MacKeychainDomain::User, …)` で login keychain の項目を引く（keyring 3 の apple-native と同じドメイン）。`security add-generic-password` で作った項目を読めること、無い項目が `NoEntry` になることを実機の Keychain で確かめた。[orchestrator-core](/components/orchestrator-core.md) の依存の記述も合わせて直した。
