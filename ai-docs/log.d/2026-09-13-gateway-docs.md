* **Creation**: [Event Gateway 構築手順](/operations/event-gateway-setup.md) と [Event Gateway（イベントゲートウェイ）](/glossary/event-gateway.md) を新設し、[Slack セットアップ Quickstart](/operations/slack-quickstart.md) に**受信方式の選択**を足した（#663、[ADR-0072](/decisions/adr-0072-slack-event-gateway.md)）。Quickstart はこれまで **Socket Mode を「選ばれた方式」として書いていなかった** —— 唯一の方式として手順に溶け込んでおり、`event_source` に相当する分岐点が文書上に存在しなかった。しかも **Socket Mode と Request URL は Slack アプリ単位で排他**なので、**アプリを作る前に方式を決めないと manifest ごとやり直し**（トークンも全部再発行）になる。分岐を手順 1 の中の枝にするとこの排他性が伝わらないので、**手順 0 として、アプリ作成の手前に置いた**。**1 ページ維持 + GCP 構築だけ別ページ**という構成にしたのは、共通部分（トークン保管・`totsuka setup`・トラブルシューティング）を複製した瞬間に片方だけ古くなるからである。分けた新ページは冒頭で「**Socket Mode で運用するならここから先は一切要らない**」と断り、`allUsers` の組織ポリシー確認（`constraints/run.managed.requireInvokerIam`）を**手順 0 に置いた** —— 通らないと構成そのものを考え直すことになるためである。`min_instance_count = 0` と `max_instances` の上限が費用の前提であることも、調整項目ではないとわかる書き方にした。Quickstart 側は手順 1（どちらの manifest か・App-Level Token と signing secret の使い分け・**Request URL が 2 箇所要る**こと）・手順 2（signing secret は `config.toml` に書かない）・手順 4（`doctor` が見るものの違い）に差分を併記し、トラブルシューティング表に Gateway 固有の 5 行を足した。**そのうち 1 行は「設定を書き換えるだけで方式を切り替えようとした」** —— `event_source` を変えても Slack 側は何も変わらないので、これは実際に踏まれる。生成物は `docs/slack-setup.{md,ja.md}` の再生成と `docs/event-gateway-setup.{md,ja.md}` の新規生成で、手書きの `docs/index.{md,ja.md}` にも行を足した。レビューで 3 件直した。**①手順 2 が「利用者ごとに 3 つ」と言い切っていたが、`operators` は 5 フィールドの object で `google_principal` が必須である** —— 書いたとおりに値を揃えた読者は `tofu apply` で型エラーに当たる。4 つに直した。**②手順が循環していて、書いたとおりには進めなかった** —— Request URL に入れるホスト名は `tofu apply` の結果で、`tofu apply` に入れる signing secret は Slack アプリの結果なので、「アプリ → ホスト → apply → signing secret → アプリ」で一周する。**アプリだけ先に作り、`<gateway-host>` はプレースホルダのままにする**（Slack が Request URL を検証するのは保存時で、manifest から作る時点ではまだ検証されない）という割り方を、Quickstart の手順 0 と構築手順の手順 2 の両方に書いた。**③生成ページの末尾が生成元ではなく ADR を指していた** —— `human-docs` の「相互参照を書く」は**対応する生成元**を 1 行で示すと定めており、落とすものの一覧には ADR 番号が入っている。既存 6 本はすべて自分の生成元を挙げており、`docs/index.md` 自身も「各ページは末尾で生成元を示す」と書いているので、規約どおりに差し替えた。あわせて `human-docs` スキルの生成マップの表が **Discord の 1 行を落としていた**のを直した（表は写しで正は宣言のほうだが、写しが誤っていると次に読む人が誤る）。
