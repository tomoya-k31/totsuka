* **Update**: `[tools.{name}]` にモデル / 推論強度の書き方を追記した（[#473](https://github.com/tomoya-k31/totsuka/issues/473)、[設定リファレンス](/development/config-reference.md)・[設定例集](/development/config-examples.md)）。**専用キーは無く `command` のフラグで指定する**という事実がどこにも書かれておらず、`ToolConfig` が `deny_unknown_fields` なので表を見た読者が「無い＝できない」と読む余地があった。綴りは totsuka の抽象ではなくツール CLI のものなので kind ごとに違い、**totsuka が起動するのは対話 CLI** である点が効いてくる: claude は `--model` / `--effort`、codex は `-m` と `-c model_reasoning_effort=<value>`（専用フラグ無し・**CLI は値を検証せず**最初のリクエストで API が弾く）、opencode は `-m` のみで、推論強度の `--variant` は **`opencode run`（非対話）専用で対話 TUI には存在しない**。opencode 側の `opencode.json` でエージェントに `variant` を置く回避は、公式スキーマが「そのエージェントに**設定されたモデルを使うときにのみ**適用される」と定義しているため `command` の `-m` と併用すると効かない可能性がある（未実測なのでそう書いた）。罠 2 つ — `mode_args` / `plan_args` は kind 既定を丸ごと置き換えるので `plan_args = ["--effort", "low"]` は plan モードの境界ごと消すこと、`command` は `split_whitespace()` なので空白を含む単一引数を書けないこと — も併記した。**専用キーの新設はしていない**（kind 横断の抽象を作る設計判断になるため、今の仕組みでどう書くかだけを書いた）。
