* **Update**: [設定リファレンス](/development/config-reference.md) に `plugins/github.toml` の節を追加した。slack と herdr の節はあったのに GitHub だけ無く、手で設定する人は Rust の構造体を読むしかなかった。全キー（`token` / `owner` / `owner_type` / `project_number` / `status_field` / `github_login` / `in_progress_statuses` / `status_map` / `repos` / `source_name` / `api_url` / `max_retries` / `[prompts]`）を既定値つきで書き、`deny_unknown_fields` なのでタイポが `initialize` の硬い失敗になることも明記した。
* **Update**: [task-source-github](/components/task-source-github.md) に「トークンに必要な権限」を追加した。**これまでリポジトリのどこにも書かれておらず**、他人が GitHub 経路を立ち上げる直接の障壁だった。呼んでいるのは GraphQL の 5 操作だけ（Project アイテム取得 / id 解決 / `updateProjectV2ItemFieldValue` / `addComment` / `viewer`）で REST も Contents API も使わない、という**確定した事実**から、fine-grained PAT なら Metadata: Read + Issues: RW + Projects: RW（Contents は不要）を導いた。**スコープ名は GitHub API の性質でコードからは検証できないので「導出であって未実測」と明記し、`verified` は付けていない。** 併せて、**PR を開くのはこのトークンではなくエージェント自身の `gh` 認証**であること（`gh auth login` が別個の前提条件であること）を書いた — これも今までどこにも書かれていなかった。
