* **Update**: [task-source-github](/components/task-source-github.md) / [設定リファレンス（config.toml）](/development/config-reference.md) — #542: GitHub Project を**複数**同時に polling できるようにし、リポジトリ → ボードの対応をそこから作るようにした（[ADR-0056](/decisions/adr-0056-multi-tracker-routing.md)）。トップレベルの `owner` / `owner_type` / `project_number` / `repos` は **`[[projects]]` の配列**へ移り、`owner_type` はエントリごとに指定できるので user 所有と org 所有のボードを混在させられる。`status_field` / `status_map` / `in_progress_statuses` / `prompts` / `token` はトップ共有のまま — ボードごとに列名が違う運用はありうるが今の要件に無く、先に入れると「効いていない設定」を作るため。**`source_name` は据え置き**なので `[[workflows]].source = "github"` の結合は無傷で、ワークフロー定義は 1 行も変わらない。
* **Update**: **`[[projects]].repos` は必須・非空になった**（従来は省略可で、空 = 「Project 内のどのリポジトリでもよい」）。理由は役割が 2 つに増えたことで、ingest フィルタであると同時に **`claimed_repos`（protocol 0.5.1）の材料**になる。省略された `repos` を claim へ変換する方法は無い — ボードは自分が将来どのリポジトリを持つかを知らないからである。あわせて**同じリポジトリを 2 つのボードに書くと `config/validate` がエラー**にする（「このリポジトリの起票先」に答えが 2 つあるのは答えが無いのと同じ）。ただし**同一ボード内での重複は通す** — 両方が同じ行き先を指すので曖昧ではなく、これを弾くと検査を無視する癖がつく。
* **Update**: **1 ボードの失敗は poll 全体の失敗にした。** そのボードを飛ばして残りを返すと、トークン失効やボード削除が「いま取り込むものが無い」と区別できなくなり、静かなボードと同じ見た目になって表に出てこない。
* **Update**: **`task/update_status` はボードを逆引きする。** `TaskUpdateStatusParams` は `{task_id, status}` だけで、どのボードの item かを request が語らない。ingest 時に `task_id → [[projects]] の index` をプロセス内メモリに覚え、それを先頭にして**全ボードを順に試す**。メモの外れは異常ではなく通常である（再起動でメモは消えるがタスクは残る／item は後からボード間を移動しうる）ので、**メモは最適化であって前提ではない** — 常に全ボードを候補に残し、見つからなければ試したボードを全部名指しするエラーになる。`task_id` をボードごとに前置修飾する案は採らなかった: `Task.id` は冪等キー `UNIQUE(source, source_task_id)` の構成要素で、変えると既存タスクの同一性が壊れる。
* **Update**: **移行案内は実装しない**という判断を記録した。旧レイアウトの設定は `deny_unknown_fields` で `initialize` の硬い失敗になるが、書き換え方を出すコードは置かない。totsuka は #542 の時点でまだ非公開で、既存の設定ファイルは実運用 1 本と live-e2e 1 本の合計 2 本しかなく、どちらも #542 の作業で書き換えるため、案内を受け取る相手が存在しない。**この判断は「利用者が作者 1 人」という現時点の事実に依存している**ので、public 化（#506）より後に同種の破壊的変更をするなら決め直すこと。
