* **Update**: `totsuka task export` のレビュー指摘を反映した（[#463](https://github.com/tomoya-k31/totsuka/issues/463)、[state.db](/data/state-db.md)）。(1) `ExportedEvent.detail` を `Option<Option<Value>>` にし、**「`--no-detail` が落とした」（キー無し）と「その行に detail が無かった」（`"detail": null`）を区別**できるようにした — 潰すと `--no-detail` で取ったアーカイブが「どの遷移が detail を持っていたか」に答えられず、DB に戻るしかなくなる。(2) **存在しないタスク id を `--task` に渡すと `not_found` で失敗する**ようにした（`show` / `cancel` / `retry` と同じ扱い）。空の書き出しは「そのタスクは何もしていない」と読めてしまう。使い切った `--since` カーソルは本物の答えなので従来どおり成功して空。(3) **broken pipe の挙動をテストで固定した** — パイプバッファ超えの出力を用意して読み手を途中で落とす形。書き込みエラーに文脈を足す程度のごく普通の編集で黙って壊れうるため、実測だけでは足りない（修正を無効化すると exit 1 になることまで確認）。(4) **出力が保存バイト列と一致することを全行突き合わせで固定した**（`export_detail_round_trips_byte_for_byte`）。書き込み側も `serde_json::Value` を通るので構造上そうなるだけで保証ではなく、監査チェーンが出力行をハッシュする用途がこれに依存する。なお「読み取り中のロックが稼働中の orchestrator の書き込みを止める」という指摘は**実測で否定**した — `state_db.rs` は WAL を設定しており（`journal_mode = WAL` はファイルに永続）、walk を 3 秒開いたまま保持しても並行する書き込みは 285µs で成功する。
