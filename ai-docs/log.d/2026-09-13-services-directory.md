* **Update**: イベントゲートウェイの置き場を `slack-event-gateway/` から **`services/slack-event-gateway/`** へ移し、`contracts/` にディレクトリ自体の README を置いた（[ADR-0072](/decisions/adr-0072-slack-event-gateway.md) 決定 9 に追記）。ルート直下は `ai-docs/` `contracts/` `crates/` `docs/` `plugins/` `scripts/` と**複数形のカテゴリ**で揃っていて、`slack-event-gateway/` だけが固有名詞の単数エントリだった。`crates/` にも `plugins/` にも入れられない理由（前者は全員の `cargo build --workspace` に乗り、後者は arch-lint が `plugin.toml` と一致する bin を要求する）は決定 9 のままなので、**3 つ目のカテゴリを足して受ける**ことにした —— 2 つ目のサービスが来たときに居場所を考え直さずに済む。`tofu/` はサービスの中に残す: 登録表の形・環境変数名・ポートが `registry.rs` と一致している必要があり、レビューで実際にそこがずれた。`.dockerignore` が既に `tofu/` を除外しているので、ビルドコンテキストの汚染も起きない。**適合スイート（`contracts/slack-event-gateway/`）はルート直下に据え置き。** 読み手が 2 つの別々の Cargo workspace にあり、しかも片方はフォークされうる（決定 9）ので、「所有者の crate の中に置く」既存の作法（`plugins/agent-ide-herdr/schemas/`、`crates/plugin-protocol/tests/fixtures/`）とは前提が違う —— どちらの precedent も読み手が 1 つで、正がどちらにあるかが決まっている。その線引きを `contracts/README.md` に明文化した（「ビルドの外に読み手がいる」かつ「どちらも参照実装ではない」の両方が成り立つときだけここに入る）。移動そのもので壊れる箇所は無かった: 両側の適合スイートは `CARGO_MANIFEST_DIR` から**上へ辿って** `contracts/slack-event-gateway/cases` を探す実装なので、段数を持っておらず無修正で通る。書き換えたのはパス文字列だけで、`.gitignore` は `/services/*/target` と `/services/*/tofu/.terraform/` に**メンバーを glob 化**した（2 つ目のサービスがここへ戻ってくるのを忘れないため）。ghcr のイメージ名 `totsuka/slack-event-gateway`・Cloud Run のサービス名・Pub/Sub のサブスクリプション名は**ディレクトリではなくサービスの名前**なので変えていない。
