* **New**: `.github/workflows/herdr-schema-watch.yml`（日次 cron）。herdr の最新 **stable** タグを取得し、スライスがコミットされていなければ取り込み用の issue を立てる（#520 §2、[ADR-0055](/decisions/adr-0055-herdr-schema-typed-wire.md)）。**prerelease は見ない** — preview ビルドは基底 stable の `version` を名乗るので、混ぜると同じ版が何度も「新しい」と判定される。同じ版で毎日立てないよう、開いている同題 issue を先に探す。互換検査を新しいスライス込みで走らせ、その出力を issue 本文に載せる — **そこが赤いのはこのジョブの失敗ではなく、報せたい中身そのもの**なので `|| true` で拾う。`audit.yml` の日次 cron が前例。ランナーは `ubuntu-slim`（`gh` / `curl` / `jq` のみ・Docker も特権操作も無し・失敗してもリリースを止めない）。
* **Update**: [agent-ide-herdr](/components/agent-ide-herdr.md) に **`wire::FLOOR` / `wire::NEWEST_CHECKED`** を生成するようにし、`NEWEST_CHECKED` より新しい herdr に warn を 1 行出すようにした（#520 §2）。**拒否ではない** — 意味するのは「この版までは CI の schema 差分が突き合わせている」だけで、それより新しい herdr は*未検証*である。**`config validate` の答えには載せない**: そこは `errors` しか運ばないので、「未検証」をエラーとして返すと動いている環境で `totsuka doctor` が赤くなる。warnings チャネルを足すのはプロトコル変更で、これには見合わない。
* **Update**: `scripts/herdr-types-build.sh` の rustfmt 必須チェックを**生成経路に限った**。`--fetch` は jq と curl しか使わないので、Rust ツールチェインの無いランナー（日次 cron の `ubuntu-slim`）でも回せる。**必要な依存を入口で一律に要求すると、その依存を使わない経路まで巻き添えで落ちる。**
