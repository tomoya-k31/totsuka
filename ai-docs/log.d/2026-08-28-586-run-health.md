* **Added**: ランタイム health（#586、F-110）。`run` が毎サイクル `$XDG_STATE_HOME/totsuka/health.json` を temp+rename で置き換え、graceful shutdown で削除する。これで `totsuka menu` に **`⚠`（生きているが仕事を全部はできていない）** が入り、可用性が `○` / `✕` の 2 値でなくなった。**この機能が存在する理由は 1 つのケースにある** —— `hook receiver failed to bind` の run はプロセスとして元気なまま**全タスクの完了検知が死んでいる**が、外から見ると健全に見える。入れるのは **「今もそうか」を毎サイクル問い直せる事実だけ**（hook receiver の bind 失敗 / プラグイン停止 / spool バックログ / LLM 鍵の 401·403）で、一過性の失敗（`notify delivery failed`・`worktree cleanup failed`）は再評価できず**永久に消えないフラグ**になるため入れない。同じ理由で **spool は `*.jsonl` だけ数え、隔離済みの `.corrupt` は数えない** —— あれは自動回収されないので、数えると人間が消すまで `⚠` が点きっぱなしになる（`doctor` の `hook-spool` チェックの担当）。LLM 鍵は `AuthLatchRouter` が 401/403 をラッチし**成功した呼び出しで自動解除**する（鍵の失効は picker への縮退にしか見えないので、外から見えるようにする必要がある）。散文は保存せず `Degradation::message()` が読み出し側で組み立て、未知の `kind` も `Unknown` として行を残す（`wait_reason` と同じ作法で、アップグレードした binary が古い記録を現在の文言で説明できる）。

* **Note**: **置き場所は state.db ではなく state ディレクトリのファイル**にした。スキーマを上げると、それより古い totsuka がその DB を開くのを拒否する（ADR-0017）ためで、メニューバー表示のためにダウングレードの壁を立てる価値はない。加えて `run.lock` が既に「今動いているプロセスについての事実は DB の外」という線を引いており、health はまったく同じ種類の事実である。**読み出しでは `run.lock` が health より優先する** —— SIGKILL された run は `health.json` を残すが、それは存在しないプロセスの話なので `✕` を `⚠` で塗り替えてはならない（`pid` も突き合わせる）。**レビューで穴が 1 つ見つかった**: `run.lock` が生きていることだけを条件にすると、プラグイン呼び出しでハングした run（pid は生きたまま cycle が止まる）の凍結した health を無期限に「今の真実」として採用してしまう。`recorded_at` を publish しておきながら、どの読み手も見ていなかった。120 秒 republish が無い文書は stale として扱い、**捨てずに縮退の 1 行として出す**ようにした —— 捨てると「黙った run について健全と報告する」ことになる。stale は run が publish するものではなく読み手の判断である（黙った run は自分が黙っていると書けない）ため、`status --json` は `recorded_at` と `stale` の両方を出して外から判断できるようにしてある。あわせて `totsuka status` にも `degraded:` ブロック（`--json` では `health`）を足した。メニューバーだけが知っている状態を作らないためで、仕様 §7 の「CLI の出力品質を UX と定義する」に沿う。
