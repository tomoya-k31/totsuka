* **Creation**: [Event Gateway の OpenTofu モジュール](/infrastructure/slack-event-gateway-tofu.md) —— `tofu apply` で Cloud Run 1 サービス・利用者ごとの Pub/Sub トピックとサブスクリプション 2 組・Secret Manager の登録表・利用者を自分のキューだけに閉じる IAM が立つ（#661、[ADR-0072](/decisions/adr-0072-slack-event-gateway.md) 決定 6・9・10・11）。**リポジトリが提供するのは構築手順とそれを自動化する OpenTofu に限る** —— 実運用のデプロイ先は利用者が用意するので、GCP プロジェクト ID も Slack アプリ ID も登録表の中身もここには入らない。**費用の前提 2 つを変数で縛った。** `min_instance_count = 0` は調整項目ではなく「月 1 ドル程度で済む理由そのもの」で、1 以上にすると待ち時間が課金対象になり桁が変わる。`max_instances`（既定 4）は、**公開側の関門が 3 つともコンテナの中で評価される**（決定 11）ため**署名で弾いたリクエストもそのためのコールドスタートも課金される**ことへの対処である —— 手前の IAM 層が無い以上、既定の 100 までスケールできる状態は費用の前提と噛み合わない。公開は `invoker_iam_disabled = true` で、**組織ポリシーには一切触れない**。ただし管理者は `constraints/run.managed.requireInvokerIam` でこの無効化自体を制限でき、適用されていればこの構成は成立しない（外部 LB も助けにならない）ので、apply の前の確認コマンドを README と infrastructure ドキュメントの両方に置いた。**既定に入れないものを 2 つ明記した** —— 送信元 IP 制限（Slack は安定したアドレス一覧を公開しておらず、推測で組めば配信を落とし始め、その累積こそが購読の自動無効化の条件である）と VPC Service Controls（pull 側を社内に閉じると自宅や出張先から引けなくなり、それは本設計がまさに想定している使い方である）。実装上の落とし穴を 3 つ潰した: `deletion_protection` は provider 既定が true で、そのままだと `tofu destroy` が**利用者が選んだ覚えのない設定**で失敗する。サブスクリプションの `expiration_policy.ttl` は既定 31 日で、**長期休暇の人のキューが黙って消え**、復帰後の症状は「totsuka が何も受け取らない」になる。`var.operators` を `sensitive` にすると `for_each` に使えない（リソースのインスタンスキーが plan 出力と state アドレスに出るため）ので、**秘密でない `key` だけを `nonsensitive` で取り出して**反復し、秘密の本体はリソースの中でキー引きする。レビューで 7 件直した。**①シークレットのマウントを `latest` から版の正確な指定に変えた** —— これが 2 つの欠陥の根で、(a) サービスと版のあいだにグラフ上の辺が無いため**初回 apply が版より先にリビジョンを作って失敗しうる**（2 回目は通るので再現しない）、(b) 利用者を足してもサービス側の引数が1 つも変わらないため**リビジョンが作られず、稼働中のインスタンスは回収されるまで古い表を配り続ける** —— 「1 人足して apply」が「いずれ有効になる」の意味になっていた。**②`google-beta` をやめて GA プロバイダにした** —— `invoker_iam_disabled` は GA の引数リファレンスに Beta 注記なしで載っており、上流スキーマにも `min_version: beta` が無い。registry の**例**が `google-beta` を使っているのは GA ページにもそのままコピーされているだけで、権威は引数リストのほうである。**③`.gitignore` が `terraform.tfvars` という名前しか弾いていなかった** —— `prod.auto.tfvars` は自動読み込みされるごく普通の置き方で、その名前にした人は全利用者の signing secret を素通しできた。守りたいのは名前ではなく中身なので `*.tfvars` + `!*.tfvars.example` にした。**④`.terraform.lock.hcl` は逆に commit すべきファイルだった** —— 秘密は入らず版とハッシュだけで、`Cargo.lock` を commit しているのと同じ理由である。あわせて `versions.tf` の制約に上限（`~> 6.0`）を入れた。残る 3 件は、存在しない変数 `registration_secret_version` を案内していた記述（state に秘密が入るのは**このモジュールでは避けようがない**と書き直した）、未作成のドキュメントへの前方参照、`service_name` の長さ検証（`<name>-sa` がサービスアカウント ID になり GCP の 30 文字上限に当たる）である。CI では、このディレクトリが変わった PR でだけ `tofu fmt -check` / `tofu validate` を回す —— 属性名の打ち間違いは、他所の誰かの `tofu plan` まで誰も気づかない類のものである。
