* **Update**: [orchestrator-cli](/components/orchestrator-cli.md) — `totsuka setup` のレシピが **Project の Status 列名を決め打ちしなくなった**。従来はワークフロー断片に `実装待ち` / `レビュー待ち` / `設計待ち` / `設計レビュー待ち` が日本語リテラルで埋め込まれており（4 種 6 箇所、2 レシピ）、**他言語のボードでは存在しない選択肢にマッチする config が書かれていた**。壊れ方はこのプロジェクトで最悪の形で、config は valid・`doctor` は緑・`run` が何も拾わない。断片を `{{implement_status}}` 等のプレースホルダにし、レシピが `StatusSlot`（key / prompt / default）でどれを使うか宣言し、interview が聞いた答えで `build_config` が置換する。
* **Update**: 対話で出る候補は**役割を説明する英語名**（`Ready to implement` → `In review`、`Ready to design` → `Design review`）。これは**フォールバックではない** — `statuses` を欠く answers ファイルは既定で埋めるのではなく、**足すべきキー名を名指しして拒否する**（`MissingStatus`）。選んでいない列名を黙って書けば、まさにこの変更が消そうとしている無言の失敗を replay 経路に残すことになる（Playbook が別マシン用に推奨している経路である）。**`ANSWERS_VERSION` は 2 のまま**でよい — 版が守るのは「古いファイルが違う意味になる」変更で、読むのを拒否するのは厳しくするだけであって意味を変えない。旧形式のファイルが実際に拒否され、キー名が 4 つとも出ることをテストで固定した。Status 列を使わないレシピの古いファイルは従来どおり通る。
* **Update**: **双方向の整合テスト**を入れた。宣言の無いプレースホルダは利用者の config に literal `{{foo}}` として届き、使われないスロットは答えを黙って捨てる —— どちらも単体では誰も気づけない。両方向とも、違反を注入すると実際に落ちることを確認した。併せて、計画の確認画面に**置換後の trigger と on_success をそのまま表示**するようにした。列名の誤りは実行してからでは無言なので、まだ「いいえ」と言える場所で見せる必要がある。
* **Update**: `--answers` の `[statuses]` に、レシピが宣言していないキーがあれば `initialize` ではなく**パース時に拒否**するようにした（`AnswersError::UnknownStatus`）。`deny_unknown_fields` は map の中を見ず、置換はレシピ側から引くので、タイポしたキーは黙って捨てられて既定値が書かれる —— `setup --answers` は成功、`validate` も `doctor` も緑、`run` だけ何も拾わない。**この変更が消そうとしている失敗そのものが、Playbook が別マシン用に推奨している経路に残っていた。** 併せて、答えは TOML の基本文字列へ埋め込まれるので**エスケープする**ようにした（`"` を含む列名は全質問の後に不透明なパースエラーで中断し、`Ready", labels = ["x` のような値は**構文的に妥当な** trigger に誰も頼んでいないキーを足せた）。計画の `when` / `then` 行は、config を実際に書くときだけ出す（既存ファイルを残す場合に出すと、`apply` が書かない値を見せることになる）。
