* **New**: [ADR-0055 herdr Socket API を下限版の schema から生成した型で受け、互換を CI で機械検査する](/decisions/adr-0055-herdr-schema-typed-wire.md)。ユーザごとに herdr の版が違う以上、必要なのは 1 点への追随ではなく**幅を持ったサポート**である。方針は**実行時は寛容（追加を無視）・CI は厳格（削除と `required` 追加で落とす）**。型は**下限版（0.7.5）のスライス済み schema から 1 組だけ生成**し、版ごとの分岐は作らない — 古い版は生成元そのものなので定義上読め、新しい版は未知フィールド無視 + `#[serde(other)]` で読む。**下限版の型で読めること自体を CI の schema 差分が検査する** — 落とすのは削除・プロパティが写る Rust の型の入れ替え・result の `required` から外れること・request への `required` 追加・enum バリアントの削除で、**落とさないのは** `pattern` / `maxProperties` のような制約の厳格化と schema に出ない振る舞いの変化（#521）。「新しい版は追加しかしない」と書くとこの検査より強い主張になる。逆向き（最新版から生成）は新しく `required` になったフィールドを古い版が送らずデシリアライズが落ちるので採らない。**上限は設けない。**
* **New**: [agent-ide-herdr](/components/agent-ide-herdr.md) に `wire` モジュール（生成物）と `schemas/` を追加。`plugins/agent-ide-herdr/schemas/` にスライス済み schema 3 版（0.7.5 / 0.8.0 / 0.8.2、各 38KB）と手書きの対応表 `methods.json` を置き、`scripts/herdr-types-build.sh` が下限版から `src/wire.rs`（46 型）を生成する。`scripts/herdr-schema-check.sh` が CI で drift と互換を検査する（`clippy / rustfmt` ジョブの `arch-lint` の隣）。**PR の CI は最新版を取りに行かない** — herdr のリリース直後に無関係な PR が全部赤くなり、ネットワーク障害でも落ちるため。
* **Update**: 互換検査で分かった 3 つの罠を記録した。①**herdr の schema は method と result を結び付けていない**（`success_response.result` は `type` の const で判別する 57 分岐の `oneOf`）ので、対応表は機械的に取り出せず手書きが一次情報になる。②**`required` の追加を一律に落とす設計は誤り**で、読む側（result）では保証が強まるだけなので通し、落とすのは `required` から**外れる**ほう。落とすべき `required` の追加は送る側（request）だけ。③**rustfmt は生成の必須依存**で、整形の有無が生成結果を変える（1 フィールドの enum バリアントが 1 行に畳まれる）ため、無いと生成物が環境で揺れて drift 検査がその揺れを差分として報告する。
