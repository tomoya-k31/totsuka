* **Update**: [orchestrator-core](/components/orchestrator-core.md) — run のサマリが、**報告済みで未読のプラグイン死を数え落とす**穴を塞いだ（#512）。ループの終了判定は `select!` の**前**にあるため、チャネルに入った `PluginEvent::Closed` を一度も読まずに break しうる。結果として同じ `run --json` が `stats.plugin_crashes: 0` と、そのプラグインを殺した dispatch の `outcomes.crashed: 1` を同時に出せた。数字を書く観測者が 2 つ（RPC 呼び出し側がトランスポート断を、`on_plugin_closed` が子プロセスの終了を）あり、遅れうるのは後者だけである。サマリ構築の直前に `try_recv` で drain し、**計数だけ**を行う（`count_plugin_crash` を `on_plugin_closed` から切り出した）。**teardown は走らせない** — `fail_sessions_of` は進行中タスクを `Failed` にして graceful shutdown の契約に反し、しかも書き戻し RPC を await するので「終了を決めた後で最大 120 秒ハングする」経路になる。`schedule_restart` も、消費するループが残っていない relaunch を予約するだけである。**塞いだのは「報告済み・未読」の窓だけで、監視タスクがまだ子の終了を観測していない場合は依然として数えられない** — だからこそクラッシュ計数の契約は、壁時計に依存する e2e ではなく条件を待つ `plugin_supervision.rs` が固定している。drain 自体はクレート内の単体テストで決定的に固定した（`run` を呼ぶ前にイベントを入れ、grace 0 で 1 周目に break させる。drain を外すと落ちることも確認済み）。
