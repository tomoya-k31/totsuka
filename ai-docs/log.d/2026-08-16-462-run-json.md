* **Update**: `totsuka run` に `--json` を追加した（[#462](https://github.com/tomoya-k31/totsuka/issues/462)）。`RunSummary` / `RunStats` を `Serialize` にして stdout へ 1 ドキュメント出す。これまで `run` の結果は散文だけで、失敗タスクを拾って再投入する・CI で done 数を検査するといった合成が全部 grep になっていた（プラグイン層は stdio NDJSON の完全なフィルタなのに、CLI 表層だけが閉じていた）。**stdout への書き込みは `print_summary` と dry-run の 1 行だけ**で、config error/warning・hook token 助言・回復の要確認はすべて stderr、core ライブラリとプラグインは直接出力を一切持たない（すべて tracing 経由）ため、「stdout はパース可能な出力だけ」の契約は構造的に保たれる。**`--dry-run` とは `conflicts_with` で排他**（exit 2）— protocol 0.2.0 で全ソースが push 型になって以降 `Engine::dry_run()` は常に空 Vec を返し、`DryRunEntry` の生成箇所は 0 件なので、JSON にしても「プレビューできない」を空配列で言い直すだけになる。**終了コードは summary から導出しない**（失敗タスクを正しく記録した run は仕事を果たしているので `failed > 0` でも 0 のまま）— 判定は `jq -e '.stats.failed == 0'` のように呼び出し側が行う。`main::wants_json` にも登録したので、`--json` 指定時のエラーは JSON エンベロープで出る。
